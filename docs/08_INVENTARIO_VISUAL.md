## Reglas comunes de pantallas

Cada página deberá mostrar carga breve sin bloquear navegación, un vacío con siguiente acción cuando no haya registros, error recuperable sin perder formularios, éxito explícito tras guardar y validación servidor. Las listas usan búsqueda/filtros/paginación con estado consistente; las operaciones que cambian inventario muestran estado pendiente y evitan segundo envío. Cada ruta debe funcionar al abrirla directamente y con teclado. Ninguna métrica se sustituye por cifras del prototipo. El diseño P16 es una galería de estados, no un dato comercial.

### Diferencias entre prototipo y producto

- El prototipo navega con `state.page`, usa datos ficticios e inserta HTML dinámicamente. La implementación deberá usar páginas/rutas reales, HTML escapado y cálculos en PHP.
- El HTML tiene un modal adicional de guía y galería, además de variantes de edición. No se suman a los 20 SVG numerados ni obligan a construir componentes separados.
- El diseño representa Windows y nombres de archivo `aura_*`; el sistema final funcionará en macOS con marca Adara. Conservar la composición visual, adaptar selector de archivos y comportamiento de ventanas a la plataforma real.
- Marca aparece como campo en producto, no hay pantalla de Marcas. Una tabla de marcas no se deduce del diseño; queda para T02.
- Tablas, gráficos y KPIs reflejan números de ejemplo del Excel. Cualquier comparación visual futura usará fixtures sintéticos y un estado vacío real.
